Process Simulate Tutorial

1. Logic Block และ Signal พื้นฐาน

วัตถุประสงค์การเรียนรู้

  1. เข้าใจว่า Logic Block คืออะไร และผูก Signal เข้ากับอุปกรณ์ได้
  2. ออกแบบเงื่อนไขการทำงานอย่างง่ายด้วย Logic Block โดยไม่ต้องเขียนโค้ด

Logic Block และ CEE คืออะไร

Process Simulate ใช้ Logic Block (Resource ประเภท Logic) ผูกกับ Signal ของอุปกรณ์ เช่น Gripper, Sensor, Door เพื่อกำหนดเงื่อนไขการทำงาน คล้าย Ladder Logic ของ PLC โดยไม่ต้องเขียนโค้ดข้อความ เบื้องหลัง Logic Block ทั้งหมดถูกประมวลผลโดย CEE (Cyclic Event Evaluator) — ตัวควบคุมตรรกะที่มากับ Process Simulate เอง (ตามที่แนะนำใน Basic บทที่ 1) ทำให้ Study เปลี่ยนจากโหมด Time-based เป็น Event-based Simulation ที่ลำดับงานถูกขับเคลื่อนด้วย Signal จริง แทนเส้นเวลาตายตัว — เป็นพื้นฐานเดียวกับที่ใช้ทำ Virtual Commissioning เชื่อมต่อ PLC จริงในโปรเจกต์ขนาดใหญ่

ก่อนเริ่ม: สร้าง Logic Resource จากเมนู Modeling → Logic Block แล้วผูก Input/Output Signal เข้ากับ Operation หรืออุปกรณ์ที่ต้องการควบคุม

ตัวอย่าง Logic: ประตูนิรภัยเปิดเมื่อหุ่นยนต์หยุดสนิท

// แนวคิด Signal wiring ใน Logic Block
Robot.AtHomePosition == true  AND  CycleComplete == true
    --> SafetyDoor.Open = true
Tip: ตั้งชื่อ Signal ให้สื่อความหมายเสมอ (เช่น SafetyDoor_Open_Req) เพราะเมื่อ Study มี Signal หลายสิบตัว การไล่ดู Logic Block จะยากมากถ้าตั้งชื่อไม่สื่อความหมาย
คำถามฝึกคิด: ทำไมต้องใช้ Logic Block แทนการเขียนเงื่อนไขไว้ใน Operation โดยตรง?
เฉลย: Logic Block แยกตรรกะควบคุมออกจากลำดับ Operation ทำให้แก้เงื่อนไข (เช่น เปลี่ยนเวลาเปิดประตู) ได้โดยไม่ต้องไปแก้ทุก Operation ที่เกี่ยวข้อง และดูภาพรวมการเชื่อม Signal ทั้งเซลล์ได้ในที่เดียว
