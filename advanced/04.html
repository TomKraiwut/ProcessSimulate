4. Offline Programming (OLP)

วัตถุประสงค์การเรียนรู้

  1. เข้าใจขั้นตอนของ Offline Programming (OLP) ตั้งแต่ต้นจนจบ
  2. แปลง Pose/Path ที่ Teach ไว้เป็นโปรแกรมควบคุมหุ่นยนต์จริงได้

Online กับ Offline Programming ต่างกันอย่างไร

รูปแบบขั้นตอน
Online (Teaching หน้างาน)Move Robot to Location → Record Position, Motion & Speed ผ่าน Pendant จริง → Edit/Run Program บน Controller
Offline (OLP)Create/Edit ใน Simulation Software → Upload to Simulation → Download to Controller ผ่าน USB/LAN → Run Program กับหุ่นยนต์จริง

OLP แปลง Pose/Path ที่ Teach ไว้ในซอฟต์แวร์เป็นโปรแกรมควบคุมในภาษาเฉพาะของยี่ห้อหุ่นยนต์ เช่น RAPID (ABB), KRL (KUKA), INFORM/TP (FANUC/YASKAWA) แล้วส่งไฟล์นั้นไปโหลดใช้กับ Controller จริงได้ทันที ลดเวลา Teach หน้างานลงมาก

Motion Planner (MOP): ทำไมความแม่นยำจึงต่างกันตามระดับ

เบื้องหลังการจำลองการเคลื่อนที่มีหลายระดับความแม่นยำ ให้เลือกใช้ตามความสำคัญของงาน:

ระดับความแม่นยำโดยประมาณ
Kinematics (Direct/Inverse)คำนวณตำแหน่งจากมุมข้อต่อโดยตรง เร็วแต่ไม่สะท้อนพฤติกรรม Controller จริง
DMC (Dynamic Controller Model)จำลองพฤติกรรม Controller แบบทั่วไป แม่นยำประมาณ 80% ของการเคลื่อนที่จริง
DMC + RRS (Realistic Robot Simulation)ใช้ RCS (Robot Controller Software ของแต่ละยี่ห้อ) จำลอง Cycle Time และเส้นทางใกล้เคียงหุ่นยนต์จริงที่สุด

เมื่อเชื่อมต่อ Logic และคำสั่งหุ่นยนต์เข้าด้วยกันแบบเต็มรูปแบบ (RRS + Logic + Robot Command) เรียกว่า ESRC (Emulated Specific Robot Controller) — ใช้สำหรับ Virtual Commissioning ที่ต้องการความแม่นยำสูงสุด

  1. 1ตรวจสอบว่า Operation และ Pose ทั้งหมดผ่าน Reachability และ Collision Check แล้ว
  2. 2คลิกขวา Robot → Robot Properties → Robot Setup เพื่อเลือก Controller Setup file ให้ตรงรุ่น
  3. 3เลือก Controller Version ที่ตรงกับหุ่นยนต์จริง แล้ว Browse ไฟล์ Machine Data (เช่น ALL.PRM, TOOL.CND, UFRAME.CND) จาก USB
  4. 4Import Tools และ Base Frame Data แล้วสั่ง Create/Update System Frames ให้ตรงกับหุ่นยนต์จริง
  5. 5Generate Program ส่งออกไฟล์โปรแกรม แล้วโหลดเข้า Controller ของหุ่นยนต์จริงผ่าน USB/LAN
ข้อควรระวัง: แม้ตรวจสอบใน Process Simulate แล้วว่าไม่ชนและ Reach ได้ทุกจุด ควรทดสอบ Path ที่ความเร็วต่ำในเครื่องจริงอีกครั้ง ก่อนรันเต็มความเร็ว เพราะความคลาดเคลื่อนเล็กน้อยของการติดตั้งอุปกรณ์จริงอาจต่างจากโมเดลเล็กน้อย
คำถามฝึกคิด: ทำไมต้องเลือก Robot Controller/ยี่ห้อให้ตรงกับหุ่นยนต์จริงก่อน Export เสมอ?
เฉลย: แต่ละยี่ห้อหุ่นยนต์ใช้ภาษาโปรแกรมและไวยากรณ์คำสั่งต่างกัน (RAPID, KRL, INFORM) การเลือกผิดยี่ห้อจะได้ไฟล์ ที่ Controller จริงอ่านไม่ได้ หรือแปลความหมายคำสั่งผิดจนหุ่นยนต์เคลื่อนที่ไม่ตรงกับที่จำลองไว้
