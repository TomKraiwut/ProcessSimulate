6. บันทึกและจัดการไฟล์ Study

วัตถุประสงค์การเรียนรู้

  1. บันทึกไฟล์ Study (.psz) และเปิดไฟล์เดิมกลับมาทำต่อได้
  2. มีนิสัยสำรองไฟล์ที่ปลอดภัย ก่อนไฟล์เสียหรือหาย

รูปแบบไฟล์ Study และโครงสร้างข้อมูล

Process Simulate มีสองรูปแบบการเก็บข้อมูล: แบบ Standalone (Single-User) ที่บันทึก Study เป็นไฟล์เดียว นามสกุล .psz รวม Resource, Operation, Part ไว้ในไฟล์เดียว เหมาะกับงานคนเดียวหรือทีมเล็ก และแบบ Process Simulate Multi-User ที่เก็บ Project เป็นฐานข้อมูลกลาง (Process Designer Database) พร้อมระบบ Check-in/Check-out ตาม User Account เหมาะกับทีมใหญ่ที่ต้องแก้ไข Study เดียวกันพร้อมกันหลายคน (ดูรายละเอียดที่ Advanced บทที่ 7)

ไม่ว่าจะใช้แบบไหน ชิ้นส่วน 3 มิติที่สร้างเองจะถูกเก็บเป็น Component (ไฟล์ .CO หรือ .COJT ซึ่งอิง JT Format) แยกจากไฟล์ Study หลัก ทำให้นำ Component เดียวกันไปใช้ซ้ำใน Study อื่นได้

  1. 1เลือก File → Save As แล้วตั้งชื่อไฟล์ให้สื่อความหมายพร้อมเลขเวอร์ชัน
  2. 2เลือกโฟลเดอร์เก็บไฟล์ที่มีการสำรองข้อมูล (เช่น โฟลเดอร์ที่ Sync กับระบบสำรองของทีม)
  3. 3ปิดโปรแกรมแล้วเปิดไฟล์เดิมกลับมาดูอีกครั้งเพื่อยืนยันว่าบันทึกถูกต้อง
  4. 4ทำสำเนาไฟล์สำคัญไว้อีกที่ก่อนเริ่มแก้ไขใหญ่ๆ
Tip: ตั้งชื่อไฟล์ให้สื่อความหมายและใส่เลขเวอร์ชัน เช่น Cell01_PickPlace_v03.psz แทนการ Save ทับชื่อเดิมตลอดเวลา จะช่วยย้อนกลับไปดูเวอร์ชันก่อนหน้าได้เมื่อแก้ไขแล้วพัง
ข้อควรระวัง: ไฟล์ .psz ที่มี Resource/Part จำนวนมากอาจมีขนาดใหญ่ — ควร Save เก็บไว้หลายเวอร์ชัน (ไม่ใช่ไฟล์เดียว) และสำรองไว้นอกเครื่อง เผื่อไฟล์เสียหรือ Study พังจากการแก้ไขผิดพลาด
คำถามฝึกคิด: ถ้าทำงานร่วมกับเพื่อนร่วมทีมหลายคนในไฟล์ Study เดียวกัน จะป้องกันปัญหาไฟล์ทับกันได้อย่างไร?
เฉลย: ใช้ Study Manager บริหารเวอร์ชันและสิทธิ์ Check-in/Check-out แทนการแชร์ไฟล์ .psz ตรงๆ — ดูรายละเอียดที่ Advanced บทที่ 7
