5. Collision Set และการตรวจสอบการชนขั้นสูง

วัตถุประสงค์การเรียนรู้

  1. รวมกลุ่มวัตถุเป็น Collision Set เพื่อตรวจสอบการชนอย่างมีระบบ
  2. แยกความแตกต่างของ Static และ Dynamic Collision Detection ได้

Collision Set คืออะไร

แทนที่จะตรวจสอบการชนของทุก Object ในเซลล์กับทุก Object (ซึ่งช้าและมี False Positive เยอะ เช่น หุ่นยนต์ "ชน" กับพื้นโรงงานที่ตั้งอยู่) Process Simulate ให้จัดกลุ่ม Object เป็น Collision Set แล้วกำหนดว่าคู่ไหนต้องเช็คการชนกันบ้าง เช่น "Robot A" กับ "Fixture B" แต่ไม่ต้องเช็คกับพื้นโรงงาน

  1. 1เลือก Object ที่ต้องการตรวจสอบการชน (เช่น Robot, Fixture, Tool)
  2. 2สร้าง Collision Set ใหม่ แล้วเพิ่ม Object เหล่านั้นเข้ากลุ่ม
  3. 3กำหนดคู่ที่ต้องการเช็คการชนภายใน Set นั้น
  4. 4รัน Collision Detection แล้วดูผลใน Collision Report

Static และ Dynamic Collision Detection

ประเภทลักษณะการทำงาน
Staticเช็คการชน ณ ตำแหน่ง Pose หนึ่งจุด เหมาะกับตรวจสอบจุดเริ่ม/จุดจบของ Operation
Dynamicเช็คการชนตลอดเส้นทางเคลื่อนที่ระหว่าง Pose สองจุด จับการชนระหว่างทางที่ Static มองไม่เห็น
ข้อควรระวัง: การเช็คแบบ Static เพียงอย่างเดียวอาจพลาดจุดชนกลางทาง (เช่น แขนหุ่นยนต์กวาดผ่าน Fixture ระหว่างเคลื่อนที่ แม้จุดเริ่มกับจุดจบจะไม่ชนก็ตาม) — งานที่มีอุปกรณ์หนาแน่นควรเปิด Dynamic Collision Detection ควบคู่ไปด้วยเสมอ

นอกจากรู้ว่า "ชนหรือไม่ชน" ให้ใช้ Minimal Distance (จากบท Basic 5) วัดระยะห่างที่น้อยที่สุดระหว่างคู่ Object ใน Collision Set ที่สนใจ — มีประโยชน์เมื่อ Collision Report บอกว่า "ไม่ชน" แต่ต้องการรู้ว่าเหลือระยะเผื่อความปลอดภัยแค่ไหนจริงๆ

คำถามฝึกคิด: ทำไมไม่ควรใส่ Object ทุกตัวในเซลล์ (รวมถึงพื้นโรงงานและผนัง) เข้า Collision Set เดียวกันหมด?
เฉลย: จะทำให้ Collision Report เต็มไปด้วยรายการที่ไม่มีความหมาย (เช่น ฐานหุ่นยนต์ "ชน" กับพื้นที่มันตั้งอยู่) จนหารายการที่เป็นปัญหาจริงยาก ควรแบ่ง Collision Set ตามคู่ Object ที่มีความเสี่ยงชนกันจริงเท่านั้น
